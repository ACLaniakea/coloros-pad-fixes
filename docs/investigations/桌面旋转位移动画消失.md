# 桌面控件旋转位移动画消失 —— 悬浮窗导致，非本项目问题

记录时间：2026-08-31
结论：**系统固有行为，与移植和本项目模块均无关，无需修复。**

## 现象

桌面图标/控件在重力翻转时本应有跟随位移的过渡动画。刚开机时动画完整，
**首次解锁后约 7~8 秒**变成只剩整屏切换，此后一直如此，直到重启才恢复。

## 根因

系统上只要存在**任意一个 `APPLICATION_OVERLAY` 悬浮窗**，
旋转 transition 就会被打上 `DISPLAY_HAS_ALERT_WINDOWS` 标志，
Shell 随即跳过桌面负责的远程动画，回落到系统默认整屏切换：

```
WindowManagerShell: start OnePuttTransition animation, info = {... f=...|DISPLAY_HAS_ALERT_WINDOWS ...}
FlexibleTaskTransitionHandler: no need handler this transitionInfo
WindowManagerShell: start default transition animation      ← 兜底路径
```

本机上那个悬浮窗来自 Scene（`com.omarea.vtools`）：

```
dumpsys window:
  mAlertWindows={Window{b107624 u0 com.omarea.vtools}}   mPackageName=com.omarea.vtools
dumpsys window windows:
  Window{b107624 u0 com.omarea.vtools}
    mAttrs={(112,321)(wrapxwrap) ... ty=APPLICATION_OVERLAY fmt=TRANSLUCENT
```

## 时间线证据

一次重启后连续录制 logcat（开机 → 解锁 → 之后 30 秒 → 连续翻转 8 次）：

| 事件 | 时间 | transition flags |
|---|---|---|
| 解锁瞬间的第一次旋转（id=7） | 14:23:32 起 | `SHOW_WALLPAPER|IS_DISPLAY`，**无** ALERT_WINDOWS |
| Scene 无障碍服务启动 | 解锁后约 3 秒 | — |
| Scene 悬浮窗挂上 | 解锁后约 7~8 秒 | — |
| 其后每一次旋转（id=8~14） | — | `...|DISPLAY_HAS_ALERT_WINDOWS`，全部走 default |

`am force-stop com.omarea.vtools` 后 `mAlertWindows` 清空，位移动画立即恢复，
实机确认。

## 排查过程中排除的因素

- **动画缩放**：`window_animation_scale` / `transition_animation_scale` /
  `animator_duration_scale` 全程恒为 1.0，解锁前后逐秒采样无变化。
- **省电 / 护眼 / 情景模式**：`low_power=0`，Scene 模式 `balance`，
  `screen_effect=1`，全程不变。
- **`persist.sys.oplus.anim_level`**：值为 1，是**最高档**，不是降级。
  移植 ROM 的 `/system/etc/init/init.lwky.rc` 把它挂在
  `persist.sys.rom_author.blur_intensity` 上（0→3、1→2、2→1），
  本机 blur_intensity=2 即最高动画等级，与本现象无关。
- **本项目模块**：解锁前后 `getprop` / `settings list`(system+secure+global)
  两份全量快照逐行 diff，动画相关项零差异。
- **LSPosed 模块 / osense 配置**：两处 bind-mount 的 osense 配置与原包 diff
  仅 `SupportMultiWin` 与两条多窗 PSI 规则，与旋转动画无关。

## 处置

在 Scene 里关掉悬浮窗（性能监视器一类）即可，无需改动系统。
Scene 的无障碍服务本身不触发这条路径，只有悬浮窗会。

同理，任何第三方悬浮窗（帧率显示、录屏悬浮球、小窗工具等）都会造成同样效果。
