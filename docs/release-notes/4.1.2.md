# 4.1.2

> [!WARNING]
> 仍须成对刷入 `boot-ACLaniakea-SM8650Q-droidspaces-r3.img` 与
> `vendor_boot-hyperSched-stub.img`。本版 BSP 依赖 r3 导出的符号；不要与 r2 或实验
> 内核混用。

本版针对 TB710FU 运行 OPD2513 时的长待机亮屏内存峰值。所有项目自有的 KernelSU
模块与 LSPosed APK 统一重建为 `4.1.2` / `410002`。

## 修复

* 新增 `oplus_boost_pool`：以 qcom system heap 的分配与释放调用点接入原厂同形态的
  预填池、shrinker 与补水线程。平板默认预留 192 MiB（64 MiB SurfaceFlinger、128 MiB
  camera）；不照搬 PKX110 的 564 MiB，以免在 7.8 GiB 设备上制造新的常驻压力。
* 相机池仅允许已绑定的 camera provider 消费 camera reserve；空闲哨兵为原厂语义的
  `camera_pid=1`，普通 qcom-system 客户端不能耗尽相机预留。
* 启动期设置 `debug.oplus.adaptive.preview=false`，避免电话紧凑窗口框架把平板留在
  VFX parallel-world 合成状态，进而保留大块全屏客户端合成缓冲。
* 撤销曾写入 `vendor.display.gpu_rendering=false` 的覆盖。该覆盖会破坏显示启动链，曾与
  软重启及 KernelSU 状态异常同时出现。
* SurfaceFlinger 只在开机后一次性从 `/foreground` 迁移至原厂对应的 `/sf` cpuset；不
  重启 SurfaceFlinger，不新增轮询或守护脚本。
* 全局和根 memcg 的 swappiness 与 PKX110 当前 ColorOS 基线统一为 125；apps 子组仍由
  Athena/OSense 自主管理。

## 验证

相机池实机验证：分配与释放 kprobe 均命中一次；camera provider 会话期间
`camera_pid` 从 1 转为 provider PID，池页可被消耗并回填。熄屏 9 分钟后亮屏 3 秒内
观测到 `allocstall +1`、`pgsteal_direct +63`、`pgscan_direct +64`，且无新增内核告警。

完整排查数据见
[4.1.1 卡顿与内存回收排查](../investigations/4.1.1-卡顿与内存回收排查.md) 第 19.5 节。

## 已知限制

长待机后的亮屏路径还会创建 SystemUI、Launcher、ColorFade 与 Taskbar 的不可换出图形
共享缓冲，无法由相机池替代。该版本降低相机 HAL 的同步直接回收，不保证消除所有桌面
或锁屏动画掉帧；后续应以真实人脸解锁的池峰值与帧时间继续 A/B。
