# 4.0.4

把移植过程中被弄断的 AOT 与内存链路接回原厂形态。改动集中在
`OplusBSP-Modules` 与 `FixModule` 两个包，其余模块随统一版本号重建、内容未变。

> 完整的定位过程、实测数据与被排除的假设见
> [4.0.4 内存与 AOT 排查记录](../investigations/4.0.4-内存与AOT排查.md)。

## 修复

| 项 | 说明 |
| --- | --- |
| **system_server 里 ColorOS 那半边一直在解释执行** | `oplus-services.jar` 与 `oplus-service-jobscheduler.jar` 的镜像内 odex 是移植者用裸 `dex2oat` 编的（无 `--class-loader-context`），ART 收 vdex 拒 odex。修复脚本改为遍历整条 SYSTEMSERVERCLASSPATH，并修掉三个会产出废品的 bug |
| **补回缺失的 `oplus_mm_proactive_compact`** | 它的目录没有 Makefile，构建脚本因此漏掉。补上后 `/proc/oplus_mem/fragmentation_index` 出现，原厂主动规整链路重新闭合 |
| **osvelte 节点命名与 lmkd 重挂** | 构建时 CONFIG 并集打开了 `_DBG`，procfs 根与字符设备变成 `osvelte_dbg`。改回 `osvelte` 后 `/dev/osvelte` 的属主权限标签与对照机一致，并桥接 lmkd 重新持有它 |
| **hybridswap 熄屏不停工** | `display_off` 依赖的面板通知器因平台 CONFIG 未定义而被编掉，永远为 0。加熄屏桥后 `hybridswapd` 由 31.1% 降至 0.0% 单核 |
| **撤销我们自己对 swappiness 的覆盖** | 此前一律写 `vm=125 / swapd=125`，理由只是对齐对照机。本机原厂是 `vm=160`，swapd 专用档模块默认是 200。现已交还原厂 |
| **AOT 产物加构建指纹** | 包内自带产物绑死本套 ROM。绑定前逐项校验指纹，不符就跳过并由脚本重编，装到别的移植包上不会覆盖人家原厂的产物 |

## 验证

安装后重启，逐项应为：

```
oplus_bsp: 34 loaded, 0 failed
services / oplus-services / oplus-service-jobscheduler   odex段 全 = 3
swappiness: vm=160 direct=60 swapd=200 kswapd=160
/proc/oplus_mem/fragmentation_index 存在
/proc/osvelte 下有 8 项，/dev/osvelte 为 system:system u:object_r:osvelte_device:s0
日志 swapd-screenoff: 桥已启动
```

对应命令：

```sh
grep -a 'oplus_bsp:' /data/adb/oplus_bsp.log | tail -1
for b in services oplus-services oplus-service-jobscheduler; do
  echo "$b $(grep -c "oat/arm64/$b\.odex" /proc/$(pidof system_server)/maps)"
done
cat /proc/oplus_mem/swappiness_para
ls -laZ /dev/osvelte
```

## 已知问题

- **swap 占用仍低于对照机，收益尚未测得。** 本版的 AOT 与 swappiness 两项都指向
  “更敢用 swap、更少抖动”，但目前只有刚开机的样本，需要一段正常使用后的稳态数据
  才能判断。
- **`/data/misc/apexdata/com.android.art/dalvik-cache/` 仍为空。** 原厂的 odrefresh
  路径被镜像里那批移植者产物堵死，只读分区删不掉，只能用绑定替代；镜像里因此白占
  约 340MB（system_ext）+ 60MB（my_stock）无法回收。
- **`servicemanager` 有 lazy 服务重试空转**，5 个不存在的射频服务持续重试，占
  6~7% **单核** ≈ 整机 1%。实测停用发起方毫无改善，已还原。根源是移植包仍把这台
  无基带设备当双卡手机（声明 `telephony.ims`、`multisim.config=dsds`）。
- **`oplus_synchronize` 仍不出货**，四轮四崩已结案，见 [4.0.3](4.0.3.md)。
- **手势 CE 存储的 hook 需要手工勾选作用域**：`com.oplus.gesture` 未加入 LSPosed
  作用域时仍会 `FATAL`。
