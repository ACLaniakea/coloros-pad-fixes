# 4.0.4

把移植过程中被弄断的 AOT、内存与 HybridSwap 链路接回原厂形态。改动集中在
`OplusBSP-Modules` 与 `FixModule` 两个包，其余模块随统一版本号重建、内容未变。

> 完整的定位过程、实测数据与被排除的假设见
> [4.0.4 内存与 AOT 排查记录](../investigations/4.0.4-内存与AOT排查.md)。

## 修复

| 项 | 说明 |
| --- | --- |
| **system_server 里 ColorOS 那半边一直在解释执行** | `oplus-services.jar` 与 `oplus-service-jobscheduler.jar` 的镜像内 odex 是移植者用裸 `dex2oat` 编的（无 `--class-loader-context`），ART 收 vdex 拒 odex。修复脚本改为遍历整条 SYSTEMSERVERCLASSPATH，并修掉三个会产出废品的 bug |
| **补回缺失的 `oplus_mm_proactive_compact`** | 它的目录没有 Makefile，构建脚本因此漏掉。补上后 `/proc/oplus_mem/fragmentation_index` 出现，原厂主动规整链路重新闭合 |
| **osvelte 节点命名与 lmkd 重挂** | 构建时 CONFIG 并集打开了 `_DBG`，procfs 根与字符设备变成 `osvelte_dbg`。改回 `osvelte` 后 `/dev/osvelte` 的属主权限标签与对照机一致，并桥接 lmkd 重新持有它 |
| **hybridswap 熄屏不停工** | `display_off` 依赖的面板通知器因平台 CONFIG 未定义而被编掉。改为内核 kprobe 接 Lenovo 面板真实 blank/unblank 事件，恢复 `display_off` 闸门；不再使用背光轮询或常驻 shell 桥 |
| **亮屏后 swapd 被 ColorOS HAL 延迟暂停** | `vendor-oplus-hardware-performance-V1-service` 是 ColorOS 自己的 HAL，但它对本机的 `hybridswap_swapd_pause` 写入跨过了显示事件：屏已亮时仍可能保持 `pause=1`。保留 HAL 运行；面板桥注册成功后，由内核忽略这条过期的手工暂停，屏幕状态只信任真实面板事件 |
| **slowpath 触发数百次 swapd 空唤醒** | Lenovo 6.1 的 `alloc_pages_slowpath` 是逐次分配通知，不是一加原机的 watermark 决策 hook。refault 守卫提前返回时它会反复唤醒 swapd。兼容入口改为 200ms 最多一次唤醒，正常内核唤醒路径不受影响 |
| **撤回错误的 refault 定时刷新** | r2 实测表明，5Hz `snapshotd` 轮询会让快照节奏偏离原厂事件驱动机制，却不能降低 `swapd_hit_refaults`。已恢复为仅由 `wakeup_snapshotd()` 触发、且仍受原厂 200ms 最小间隔限制；22000 页/秒门槛不变 |
| **修正 4K ZRAM 的 refault 计数范围** | 原机 64K ZRAM 通过 `is_chp_zram()` 跳过普通内存槽，私有 `fault_cnt` 在不使用磁盘层时保持 0；平板 4K 路径却在判断 `ZRAM_WB` 之前计数，导致每次普通 `pswpin` 都被当成 HybridSwap fault。现只对真正的 `ZRAM_WB` fault-out 计数，不改阈值、不屏蔽真实磁盘层 refault |
| **`zram_opt` 没有真正连到 HybridSwap** | 平板的 `free_swap_is_low_fp` 是孤立导出，HybridSwap 自己留了一份私有回调槽，原厂低 swap swappiness 保护失效。重建为 `zram_opt → HybridSwap` 依赖后，模块引用关系与原机一致 |
| **撤销我们自己对 swappiness 的覆盖** | 此前一律写 `vm=125 / swapd=125`，理由只是对齐对照机。本机模块默认是 `vm=160 / swapd=200 / kswapd=160`，现已交还本机控制面；手机的 125 档只作为参考，不直接写入平板 |
| **撤销我们自己对缓存进程上限的降档** | 我们的 BaseFix hook 一直把 AMS 缓存进程上限从原厂的 96 压到 48，是后台留存明显差于对照机的直接原因。当初压低的实测依据成立，但取自本版四项修复之前。现改为默认不干预，`persist.sys.aclaniakea.max_cached`（8~256）可按需重新降档 |
| **AOT 产物加构建指纹** | 包内自带产物绑死本套 ROM。绑定前逐项校验指纹，不符就跳过并由脚本重编，装到别的移植包上不会覆盖人家原厂的产物 |

## 验证

安装后重启，逐项应为：

```
oplus_bsp: 34 loaded, 0 failed
oplus_bsp_zram_opt 被 oplus_mm_hybridswap_zram 引用
Oplus performance HAL = running
Lenovo HyperSchedule HAL = stopped
日志 panel event kprobe registered
hybridswap_swapd_pause = 0
snapshotd 仅随有效 swapd 唤醒触发，area_anon_refault_threshold = 22000
纯 ZRAM 换入时 hybridswap_stat_snap 的首个 fault_cnt 保持 0
services / oplus-services / oplus-service-jobscheduler   odex段 全 = 3
swappiness: vm=160 direct=60 swapd=200 kswapd=160
/proc/oplus_mem/fragmentation_index 存在
CUR_MAX_CACHED_PROCESSES = 96（原厂值，由 Athena 按本机产品配置算出）
/proc/osvelte 下有 8 项，/dev/osvelte 为 system:system u:object_r:osvelte_device:s0
```

修正 fault 计数范围后，开机 268 秒压力样本：

```
pswpin                 2191401
HybridSwap fault_cnt         0
swapd_wakeup                495
swapd_hit_refaults            0
swapd_shrink_anon           100
```

失败版在相近开机阶段是 `swapd_wakeup=3801 / swapd_hit_refaults=3772 /
swapd_shrink_anon=14`。修复没有放宽 22000 门槛；它恢复的是原机“普通内存 ZRAM
换入不属于 HybridSwap 磁盘 fault-out”的计数边界。

对应命令：

```sh
grep -a 'oplus_bsp:' /data/adb/oplus_bsp.log | tail -1
grep -E 'oplus_bsp_zram_opt|oplus_mm_hybridswap_zram' /proc/modules
cat /sys/block/zram0/hybridswap_swapd_pause
cat /sys/block/zram0/hybridswap_vmstat | grep -E 'swapd_wakeup|swapd_hit_refaults|swapd_manual_pause'
grep -E 'fault_cnt' /sys/block/zram0/hybridswap_stat_snap
cat /proc/oplus_mem/swappiness_para
ls -laZ /dev/osvelte
```

## 已知问题

- **高 PSI 与直接回收仍未解决。** 通过计数修复后 swapd 已恢复工作，但压力样本中
  `Shmem` 与 `Unevictable` 仍同步达到约 1.16GB，`pgsteal_direct` 仍高；这与 refault
  误判是两条问题，后续继续追 GPU/shmem 占用，不能把本项写成“锁屏卡顿已彻底解决”。
- **参考机的 watermark hook 不能移植。** 在 Lenovo 6.1 上实测会造成约
  424 次/秒的 swapd 唤醒，已撤销，不包含在本版。
- **`/data/misc/apexdata/com.android.art/dalvik-cache/` 仍为空。** 原厂的 odrefresh
  路径被镜像里那批移植者产物堵死，只读分区删不掉，只能用绑定替代；镜像里因此白占
  约 340MB（system_ext）+ 60MB（my_stock）无法回收。
- **`servicemanager` 有 lazy 服务重试空转**，5 个不存在的射频服务持续重试，占
  6~7% **单核** ≈ 整机 1%。实测停用发起方毫无改善，已还原。根源是移植包仍把这台
  无基带设备当双卡手机（声明 `telephony.ims`、`multisim.config=dsds`）。
- **`oplus_synchronize` 仍不出货**，四轮四崩已结案，见 [4.0.3](4.0.3.md)。
- **手势 CE 存储的 hook 需要手工勾选作用域**：`com.oplus.gesture` 未加入 LSPosed
  作用域时仍会 `FATAL`。

## 安装

见仓库 [README](../../README.md#安装)。从 4.0.3 升级直接安装两个新包并重启即可，
无需卸载旧版。若要回退，优先安装上一个完整、配套的 OplusBSP 模块包；不要混用旧
HybridSwap、旧 `zram_opt` 或其他设备的预编译 `.ko`。
