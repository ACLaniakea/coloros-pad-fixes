# 4.0.3

调度链三项 + 模块清单清理。内核沿用 v4.0.0，不需要重刷。

> 完整定位过程与实测数据见
> [4.0.3 调度链与 SELinux 排查记录](../investigations/4.0.3-调度链与SELinux排查.md)。

## 修复

| 项 | 说明 |
| --- | --- |
| **sched_assist 的负载均衡从未被触发过** | `lb_stat` 全零。新增自编模块 `oplus_lb_bridge`，把 tick 入口接回 `android_vh_scheduler_tick`（需经转接函数，直接注册导出符号会被 kCFI 拦下 panic） |
| **UX 标记没翻译成 WALT 认识的形式** | 新增 `oplus_walt_bridge`，把 `test_task_ux()` 命中的任务翻译成 `set_task_boost()`，随开机启用 |
| **帧组不给 SurfaceFlinger 提频** | 开机后补回 `stune_boost` 的 `sf_migr_gpu` / `sf_freq_gpu`（grp5-9，各 30），对齐对照机 |
| **移植时丢掉的 SELinux 放行** | 补齐 UX 线程登记、帧率提升相关规则，目标类别的 denial 归零 |
| **手势服务开机崩溃循环** | 锁屏期间把 CE 存储重定向到 DE，避免 `SharedPreferences` 在设备未解锁时崩溃 |
| **Soter Key 开机自愈** | 开机检测并修复 Soter 密钥状态 |
| **8GB 内存档交还原厂** | 撤销我们自己写的 `app_score=0` 豁免，全树交还原厂 300 |
| **移除 `oplus_resctrl`** | 它占满 `PERCPU_MODULE_RESERVE`，挤掉原厂的 `oplus_bsp_game_opt`。移除后 33 loaded / 0 failed |

## 验证

```sh
grep -a 'oplus_bsp:' /data/adb/oplus_bsp.log | tail -1      # 应为 33 loaded, 0 failed
grep -E 'tick_hit|tick_pull_runnable_ux' /proc/oplus_scheduler/sched_assist/lb_stat
cat /proc/oplus_walt_bridge                                  # ux_hits 应持续增长、errors=0
```

## 已知问题

- **桌面显存偏高**：`com.android.launcher` 的 Skia 暂存渲染目标缓存长时间运行后可涨到约
  900MB（对照机约 60MB）。真正的纹理缓存两台相同，差异全在暂存目标没被复用。这是桌面
  应用内部行为，系统属性层面没有对应旋钮，本版未处理。
- **锁的 UX 优先级继承仍然缺失**：`oplus_synchronize` 试过四轮、四轮都 kernel panic。
  期间定位并修掉三处真实根因，但每修完一处就冒出下一处；本机 ramoops 的 ECC 已损，
  取不到调用栈，继续等于盲修，故结案。源码与三处修复存档在
  `kernel-compat/oplus_synchronize/`，**不随模块加载**。
- **属性枚举拒绝**：每次进程 spawn 会遍历全部属性上下文，在受限域上产生一批
  `avc: denied`。已确认是本机独有行为，但未定位到发起者。仅日志噪声。
- **锁屏动态壁纸打拍**：`144 ÷ 60 = 2.4` 不整除导致的固定节拍，与性能无关。
- 沿用 v4.0.1：移植包重打包 vendor 时丢了 `/vendor/bin/qms` 与 `/vendor/bin/qcc-vendor`
  的 SELinux 标签，须在重打包时对 `vendor_file_contexts` 执行一次 `setfiles`。
