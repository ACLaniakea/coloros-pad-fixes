# 扬声器破音排查（2026-08-31）

硬件：AWINIC aw882xx ×4（i2c 1-0034/35/36/37），TB710FU
参照物：联想原厂 `TB710FU_CN_OPEN_USER_Q00019.0_A16_ZUI_17.5.04.414_ST_260320.7z`

## 结论

找到两处真实缺陷，都已修复，实机确认破音有改善。

### 一、播放通路被我们自己改过（主因）

`base-fix` / `fix-module` bind-mount 的 `mixer_paths_pineapple_mtp.xml` 里，
`speaker` 通路多出两行原厂没有的内容：

```xml
原厂：  <path name="speaker">
        </path>

我们：  <path name="speaker">
            <ctl name="aw_dev_0_volume" value="10" />
            <ctl name="aw_dev_1_volume" value="10" />
        </path>
```

`speaker-prot`（带保护的播放路径）直接 include `speaker`，所以正常放音必然生效。
实机验证四颗功放确实处于分裂状态：

```
aw_dev_0_volume = 10    aw_dev_1_volume = 10
aw_dev_2_volume = 0     aw_dev_3_volume = 0
```

两颗被单独改了输出寄存器、另两颗保持原厂，既造成不匹配，也让那两颗在大音量下
偏离原厂标定的工作点。

这个 bind-mount 的既定用途是**采集增益**（注释写明 "TB710FU capture gain"，
修录音音量过小），只应改 TX_DEC / ADC。这两行属于夹带进来的播放侧遗留改动，
git 历史里没有单独说明理由的提交。**已删除，采集增益部分原样保留。**

### 二、智能功放 Re 校准数据是空的

```
校准前  /mnt/vendor/persist/factory/audio/aw_cali.bin    = 40 字节全是空格
        /mnt/vendor/persist/factory/audio/aw_cali_f0.bin = 2118 2053 587 607（本来就有）

校准后  aw_cali.bin = 6575 6542 6562 6494 mΩ
```

即 f0 一直正常，唯独缺 Re。用机器自带的 `/vendor/bin/aw882xx_cali`（需要放音保持
扬声器通路激活）重新校准得到上述四个值，互差不到 1.3%，且落在驱动声明的
4000–30000 mΩ 合法区间内。校准值写在 persist 分区，重刷系统不会丢。
原始文件备份在 `diagnostics/tmp/awcali-backup/`。

## 已排除的因素（全部与原厂逐字节一致）

对照联想 ZUI 原厂包逐项比对，音频链上没有任何一处被移植方替换：

| 文件 | 结果 |
|---|---|
| `vendor/etc/acdbdata/pineapple_mtp/*.acdb` `*.qwsp` | md5 一致 |
| `vendor/etc/dolby/dax-default.xml` | md5 一致 |
| `vendor/firmware/aw882xx_acf.bin` | md5 一致 |
| `vendor/lib64/libar-pal.so` | md5 一致 |
| `vendor/lib/modules/aw882xx_dlkm.ko` | md5 一致 |
| ADSP 固件（原厂 `dspso.bin` vs 移植包 `dsp.img`） | md5 一致 |

由此也纠正了两个中途走偏的判断：ACDB **不是**高通公版参考数据而就是联想原厂那份；
`dax-default.xml` **不是**缺了设备专属调音，联想原厂本来就只有这一个文件。

### timed render 一说不成立

网传的 HyperOS 破音方案（关 `persist.timed.enable`）在本机不适用：

- `persist.timed.enable` 全盘（system / system_ext / vendor / odm 的 lib64、bin、
  framework）**没有任何模块读取**，是条遗留死属性；真正被读的是
  `vendor.display.timed_render_enable`（`init.qti.display_boot.sh` 按 SOC ID 写死 1，
  消费者是 `libcomposerextn.qti.so` 的 `smomo::TimedRenderState`）。
- 音频时钟实测无漂移：150.6 秒长窗口内 `Frames written` 增长 7230720 帧，
  即 48003.0 fps，与标称 48000 相差 0.006%。

因此没有改动任何显示栈属性。

## 遗留观察

- `aw882xx_algo_auth_tlv_rw: size != algo_auth_data` 在每次功放启动时出现，
  四颗均如此，`monitor` 也是 Disable。但 HAL、驱动 .ko、ACDB、ADSP 固件全部是原厂，
  所以这大概率是本平台常态而非移植缺陷，暂不处理。
- `get_spkr_st` 在放音时能读回 `R0 = 6506 mΩ`、`Te = 25`，证明 DSP 侧的 AW 算法
  模块存在且响应正常。

## 模块侧的处理

Re 是逐台实测数据，**不能打包进模块分发**——给所有人灌同一组阻抗值，会让智能功放
拿错误的基准去算振幅保护余量，比留空更糟。因此模块只做两件事：

- `service.sh` 的 `check_speaker_calibration()`：开机检查 `aw_cali.bin` 是否为空，
  为空则在模块日志里给出警告。（注意 toybox 的 `grep` 会把该文件判成二进制而拒绝
  匹配，检测用 `tr -dc '0-9'` 取数字。）
- `bin/aw_cali_run.sh`：辅助脚本，封装 `get_re_range` / `get_spkr_st` / `cali_all`
  三步并打印校准前后的值。**运行时必须有音频正在播放**，否则 DSP 通路未激活，
  `get_spkr_st` 会返回 `get st failed`。系统音量可以设为 0，不影响校准。

`mixer_paths` 里删掉的两行是通用修复，随模块分发。
