# 3.1.0：CryptoEng 分流、前摄指示灯与手电筒亮度

## 结论

3.1.0 不是把原厂 CryptoEng HAL 整体替换掉，而是在已经能用的查找设备软件 HAL
前面放一个很薄的 Binder 分流层：查找设备原有命令仍交给软件 HAL，互传联系人模式
缺的 PKI 命令在代理内补齐。这样不会为了修联系人模式重新破坏已恢复的注册、定位与
登出链路。

前摄指示灯同时并入 `FixModule`，不再额外装独立模块；手电筒亮度则从四档试验值改为
驱动电流 0–100 的全范围分档。

## CryptoEng：为什么要分流

共享软件 HAL 已能处理查找设备的 2001–2022 命令，但一加互传联系人模式创建 Beacon
时会调用 `10003 CeCmdRunPkiHkdf`。这个命令此前返回 `UnknownTransaction`，广播包
无法创建，其他设备自然搜不到。

`CryptoengHAL-Module` 的处理方式如下：

- `vendor.oplus.hardware.cryptoeng.ICryptoeng/default` 由 `ce_proxy` 接管；
- 共享软件 HAL 只改等长的服务实例名，作为 `backing` 保持运行；
- 10003 在代理内按原厂参数语义完成 HKDF-SHA256 派生，返回 602 类型的 JSON 响应；
- 查找设备命令和其余已实现命令仍将完整 MethodBuffer 原样交给 `backing`。

联系人 Beacon 每次都会带新的 salt，因此这里是动态派生而不是缓存一份固定 OKM。
具体协议、响应类型和回滚方式见
[CryptoEng 10003 分流代理说明](CryptoEng-10003分流代理说明.md)。

## 前摄指示灯

移植 ROM 缺少 ColorOS 对前摄 RGB 灯的控制：camera ID 1 实际被占用时，屏幕绿点能亮，
物理白灯却不亮。3.1.0 把守护脚本并入主 `FixModule`：

- 前摄真实打开时写入 RGB LED，点亮白灯；
- 释放后熄灭；
- 排除人脸解锁与 AON 造成的误判，避免无意义常亮。

因此不再需要单独安装旧版 `base-fix` 前摄灯模块。

## 手电筒分级亮度

SystemUI 不能直接写目标 LED 节点，3.1.0 仍采用“LSPosed 钩子写信箱 + root 模块监听”
的两段式路径，但输出改为 0–100 的驱动电流全范围。低亮度不再依赖不稳定的固定档位，
也避免切换时爆闪。

## 安装与验证

3.0.0 之后的模块依赖配套内核接口，因此 Release 里的两份镜像仍是**必装前置**：

```
boot-ACLaniakea-6.1.128-13.img
vendor_boot-hyperSched-stub.img
```

两者必须成对刷入；只刷其中一份会造成调度模块 ABI 不匹配，轻则功能不生效，重则无法
正常启动。它们与 3.0.2 使用的是同一对已验证镜像，SHA-256 分别为：

```
boot-ACLaniakea-6.1.128-13.img       1cbc75c92841854ea049ce44083d6183c684068304aed9c33d733cffec394d46
vendor_boot-hyperSched-stub.img       4c19254c2c6e2c808e89ae0e2764bbdb226261d8bc8595ee6e75ab39099eb558
```

需要查找设备或一加互传联系人模式时，在既有安装顺序中额外刷入：

```
CryptoengHAL-Module-v3.1.0.zip
```

主修复、内核前置条件、手写笔三件套与 Scene 调度模块的安装顺序不变，完整说明见项目
[README](../README.md)。

设备端已完成的验证：

- 查找设备注册、定位与登出仍由 `backing` 链路正常处理；
- 10003 能处理连续变化的 Beacon salt，BLE 广播可正常启动；
- 前摄物理指示灯能随 camera ID 1 开关；
- 手电筒低档位与连续亮度切换正常。

## 已知边界与回滚

联系人模式仍依赖双方 OPlus 账号手机号与本地通讯录号码的哈希匹配；联系人未命中时，
系统会按原厂策略隐藏对端，这不是 HAL 可绕过的权限条件。

要回退 CryptoEng，只需在 KernelSU 停用或移除 `cryptoeng_hal_fix` 后重启，ROM 会回到
原先的软件 HAL 路径。其他 3.1.0 修复不依赖该模块。
