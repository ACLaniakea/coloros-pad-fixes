# v4.0.1

v4.0.0 基线之上的修正发布：全部模块与配套 APK 统一为 `4.0.1 / 400001`，由当前源码重新构建。

> [!NOTE]
> 本次未变更内核。Release 中的 `boot` 与 `vendor_boot` 与 v4.0.0 内容相同，仍须成对刷入。

## 相比 v4.0.0

### 前台掉帧减半

桌面滑动掉帧率 **12.49% → 6.23%**，帧时间 p99 **150ms → 48ms**。按帧数归一后 `Missed Vsync` −53%、`Slow UI thread` −48%、`Slow issue draw commands` −59%、`Slow bitmap uploads` −77%。

`gfxinfo framestats` 逐阶段拆解把病灶指向调度而非 GPU（帧内中位 1.29ms）或内存（PSI `some avg60` 0.10）：`Vsync→HandleInput` 这段纯调度延迟 p99 达 6.92ms，而 144Hz 的帧预算只有 6.95ms。

根子在核心拓扑——本机六核 1+4+1，`cpu0` 是唯一的 A520，实测 65% 忙并承接全部 WiFi 收包中断，而 `top-app` 原本包含它。改为沿用原厂给 SurfaceFlinger（`sf` 分组）的核集合（原厂本就把 `cpu0` 排除在 `sf` 之外），并打开 `latency_sensitive`。

### 手写笔触感反馈重做

原厂触感页的三个控件在这支笔上全是死路：书写反馈与振动强度写的是 ColorOS 专有特征，本机 GATT 没有；功能反馈的原厂接口是只打日志的空实现。现隐藏这三行与试写区，改为一个直连联想触觉通路的**全局书写反馈**开关，加**五档笔触感模式**。入口跟随连接状态置灰。

传输层同时修正两处会导致「振动整体消失」的问题：不再把书写开关命令翻译到联想的触觉**总开关**特征（带关闭语义时会让笔上所有振动断电）；会话查找改为优先返回仍绑定在活动会话上的那一个（重连后残留的同 MAC 孤儿会话会让命令无人认领，1.8 秒后看门狗判死整条传输）。

### system_server 的 AOT 产物失配

移植包换过 `/system/framework/services.jar` 的主 dex（zip CRC 变了）却没重建 oat 产物。ART 校验 `services.vdex` 的五个 location checksum 时只有主 dex 对不上，而它要求全部匹配，于是整份拒绝、退回从 jar 直读——system_server 的 18MB 主体一直在解释执行加 JIT。

代价可量化：`Jit thread pool` 累计占开机时间 **5.4%**（同代 ColorOS 对照机 0.167%），解锁瞬间 JIT 独占 system_server CPU 的 20.2%。

系统自身修不了：`odrefresh` 只检查文件存在性与 ART apex 版本，因此报告 "artifacts OK" 而从不重编；它编到 `/data/misc/apexdata` 的产物又会在下次开机被当作多余清理掉。同一个 checksum 也让 `services.jar.prof` 失效，默认的 `speed-profile` 只能产出空壳。

本版随包分发已编译好的产物，由 `post-fs-data` 绑定到 `/system` 侧，**相同移植构建的设备装完重启即生效**。若构建不同，ART 会拒绝该产物（表现与修复前一致，不会更糟），模块随后在开机三分钟后于后台自动重编，参数全部从运行中的系统读取，不硬编码机型。`FixModule` 体积因此由 89.8MB 增至 127.9MB。

> [!NOTE]
> **已确认**：三个产物（`.art` / `.odex` / `.vdex`）全部被 ART 采纳，连续重启可复现。
> **未确认**：对解锁掉帧与 system_server 占用的实际改善幅度——采样窗口内有用户交互干扰，故本说明不给出收益数字。

### 稳定性与开销

- **收敛充电控制节点权限**：移植包把 `charging_enable` 等一律开成全局可写，任何应用都能停掉充电。现去掉 other 写位，属主与读权限不变，两条既有写入路径不受影响。
- **应用建议自愈改为限速**：原实现每 2.7 秒就启动一次 ART 虚拟机做无事发生的检查。限速后系统空闲期进程创建速率由 42/s 降至 19~24/s。
- **键盘自定义键**：「选择应用」页的「显示系统应用」开关此前点了没反应，现就地重过滤列表。

## 已知问题

移植包重打包 vendor 时丢了 `/vendor/bin/qms` 与 `/vendor/bin/qcc-vendor` 的 SELinux 标签，init 因此拒绝注册对应服务，`servicemanager` 会持续尝试惰性启动五个射频/数据 AIDL 接口并失败。本机没有本地调制解调器，**功能上无损失**，但会产生约 5 次/秒的无效 init 往返。这是打包阶段缺陷，模块无法修复（init 解析 rc 早于模块挂载），须在重打包时对 `vendor_file_contexts` 执行一次 `setfiles`。

## 安装或升级

请使用同一 v4.0.1 Release 的产物。内核沿用 v4.0.0，不需要重刷。

安装完 KernelSU 模块与 APK 后执行一次**完整重启**，不要仅重启 zygote。
