## 结论

3.2.0 是一次统一交付版本：主修复、手写笔、Scene 调度、OPlus BSP、CryptoEng 与
ZUI 相机移植均统一为 `3.2.0 / 302000`。模块显示名称采用项目既有的
`联想平板 Pro GT - 功能名` 风格；配套 LSPosed APK 与系统服务 APK 也同步升级，避免
KernelSU、LSPosed 与 PackageManager 显示不同版本。

本次主线重点不是更换相机 HAL，而是修正移植系统中 AON、相机 provider 与 QNN DSP
运行时之间的生命周期和命名空间关系：普通相机打开时 AON 按原框架路径让出前摄，关闭后
恢复；AON 推理继续走硬件 QNN/DSP，不改为 CPU 模拟。

## 相比 3.1.0 的完整升级

- **AON DSP 重启不稳定**：定位到 AON 私有挂载命名空间使用了与根目录不同版本的 QNN
  HTP skeleton，导致偶发 session 创建失败。现在在 AON 自己的命名空间绑定匹配 runtime，
  并恢复原厂 `0x60007 SmartFaceGaze` 生命周期；推理仍走 QNN/DSP，不使用 CPU 模拟。
- **AON 与相机争抢前摄**：相机 provider 未处理 `SIGPIPE`，会反复退出并重新枚举，之前的
  仲裁因此被伪造的开关事件打乱。provider 现在保持原域、原链接命名空间，仅忽略 `SIGPIPE`；
  普通相机打开时 AON 让出前摄、关闭后恢复的框架仲裁链路可稳定工作。
- **相机 provider 稳定性**：移植 CamX 的动态深度 tag 返回 `-22` 会触发
  `libcameraservice` 的异常路径，现已兼容处理；前后摄正常枚举，前摄物理 RGB 指示灯修复
  继续保留。
- **ZUI 原厂相机移植**：新增独立的 TB710FU ZUI 相机系统模块和只作用于
  `com.zui.camera` 的 LSPosed Hook。包含 LCAF 参数、Lenovo 原生身份层、ColorOS 相册入口，
  并处理 Hybrid Mount 下应用私有命名空间不可见纯 systemless APK 导致的黑屏。
- **手写笔构建可复现**：手写笔 Hook 的源码构建补齐完整的编译期 Xposed API stub；这些类不
  打入 APK，运行时仍由 LSPosed 提供，因此不改变现有的连接、电量、充电或振动逻辑。
- **作用域与版本一致性**：基础 Hook 补齐 `SystemUI`、`Accessory` 的推荐作用域元数据；
  ZUI Hook 只推荐 `com.zui.camera`。主修复、手写笔、调度、BSP、CryptoEng、ZUI 相机及其
  配套 APK 全部统一为 `3.2.0 / 302000`，并从当前源码重新构建。

## AON、相机与 DSP

相机 provider 在移植系统上会因未处理的 `SIGPIPE` 反复退出，进而制造错误的相机
断开/重连事件，并使 AON 与普通相机不断争用前摄。主修复模块现在保留原 provider 的
SELinux 域和链接命名空间，仅在启动构造阶段忽略 `SIGPIPE`，避免设备枚举循环。

AON 的 QNN 运行时还存在私有挂载命名空间与全局根目录加载不同版本 HTP skeleton 的问题；
这会导致重启后偶发 DSP session 创建失败。模块会在 AON 进程私有命名空间中绑定已经验证
的同版本 runtime，再恢复原厂 `0x60007 SmartFaceGaze` 生命周期。设备端已验证 AON 能
创建/销毁 QNN session，并向 `AttentionDetector` 回报成功结果。

## ZUI 相机移植

`LenovoPadProGT-ZUI-Camera-Port-v3.2.0.zip` 将 TB710FU 原厂 ZUI 相机作为系统基底
部署，并包含：

- LCAF 相机算法参数；
- 只作用于 `com.zui.camera` 的 LSPosed 兼容 Hook；
- 仅相机进程可见的 Lenovo 原生身份层；
- ColorOS 相册入口桥接；
- Hybrid Mount 兼容的同签名更新包保留策略。

该策略不替换 CamX、相机 provider 或全局系统身份。它解决应用私有挂载命名空间看不到
纯 systemless APK 时的启动黑屏，同时不扩大伪装范围。

## 手写笔与模块元数据

手写笔三件套全部从源码重建：`PenBridge-Module`、`PenBridge-Hook` 与
`PenHidCtl`。旧构建脚本缺少完整的编译期 Xposed stub，导致源码重建时无法解析
`MethodHookParam.method/getResult` 等 API；现已补齐编译期声明，运行时仍只由 LSPosed
提供实现，不改变手写笔连接、充电、电量或振动逻辑。

基础修复 Hook 的推荐作用域也已与实际功能对齐：`android`（system_server）、
`com.android.systemui` 与 `com.heytap.accessory` 均有对应 Hook，不能因 UI 漏列而取消。
ZUI 相机兼容 Hook 则只推荐并仅加载到 `com.zui.camera`。

## 安装与验证

主修复使用：

```
FixModule-v3.2.0.zip
BaseFix-Hook-v3.2.0.apk
```

手写笔使用三件套：

```
PenBridge-Module-v3.2.0.zip
PenBridge-Hook-v3.2.0.apk
PenHidCtl-v3.2.0.apk
```

按需增加：

```
SM8650Q-Scene-Scheduler-v3.2.0.zip
OplusBSP-Modules-v3.2.0.zip
CryptoengHAL-Module-v3.2.0.zip
LenovoPadProGT-ZUI-Camera-Port-v3.2.0.zip
ZUI-Camera-Compat-v3.2.0.apk
```

`base-fix` 与旧 `PortTuning` 已被合并主修复取代，不应与 `FixModule` 重复安装。

本次在平板上完成的安装后验证：

- 六个正式 KernelSU 模块均显示 `3.2.0 / 302000`；
- BaseFix、手写笔、PenHidCtl、ZUI 相机兼容四个 APK 均显示 `3.2.0 / 302000`；
- 模块内嵌的三份 Hook 与本地构建 SHA-256 一致；
- 完整重启后所有已启用模块仍正常挂载。

## 源码与发布内容

源码仓库同步本次的 Java、C/C++、smali、构建脚本、模块配置与修复文档；发布 ZIP/APK
作为 GitHub Release 附件提供。为避免仓库膨胀，不提交 OEM APK、厂商二进制库、内核镜像、
构建 ZIP/APK、SDK、日志、抓帧和临时逆向目录。这些大文件的来源、构建入口和安装关系均在
项目 README 与各模块说明中保留。

## 已知边界与回滚

ZUI 相机依然依赖本机 TB710FU 的原厂相机 APK、配置和签名，不能作为通用 ColorOS 相机
移植包使用。AON 修复保持原厂 DSP 路径；如果后续更新替换 AON APK 或 QNN runtime，需要
重新确认私有命名空间中的 runtime 版本匹配。

若需回退，先在 KernelSU 停用对应模块、卸载其配套 APK 后完整重启；不要重启 Zygote，
以免影响 KernelSU 保存的超级用户授权列表。
