# sched_ext / FengChi 策略层验证记录

日期：2026-09-04。目标内核为 TB710FU（SM8650Q，`1+4+1`）的 Android 14 / Linux 6.1.128。

## 已完成的门禁

- 2023 初始 sched_ext core 已移植进独立内核工作树，并保持默认关闭。
- Android KABI 改为 `task_struct`/`rq` 的保留槽指针；两者尺寸均与稳定内核一致。
- 已用 vendor_dlkm 289 个模块和 system_dlkm 60 个模块复核：模块 CRC mismatch 均为 `0`。
- 新内核 BTF 可生成最小 `struct_ops` 策略对象；对象包含正确的
  `sched_ext_ops` 映射和 `scx_bpf_dispatch` kfunc 重定位。

## 真实 FengChi 内容的边界

公开的 FengChi 包并未包含 HMBIRD 的 CPU 选择、任务分类、频率控制或调度决策。
其中 `/proc/hmbird_sched` 项只是独立整数变量，写入不会改变调度行为。因此不能把
它作为实际风驰调度器或将这些节点暴露给 Scene。

## 首次真机引导结论

该候选曾通过 9008 写入 `boot_a`，但没有进入 ADB；随后已立即用完整原始
`boot_a` 备份恢复，基线重新正常启动。

镜像头、打包和 vendor 模块 CRC 均已复核，内核 `.config` 相对基线唯一的差异是
`CONFIG_SCHED_CLASS_EXT=y`。因此故障在 SCX core 的早期路径，而不是 vendor_boot、
WALT 或模块 ABI。具体 panic 文本未能从 pstore 保留，不能虚构为单一指令。

当时 2023 core 的“关闭”并不惰性：它仍在 `sched_init()` 初始化 DSQ/每 CPU 状态，
并让每个 fork/free 分配和维护 `sched_ext_entity`。这会在首个 Android 用户空间
进程出现前就改变调度生命周期，是首屏失败最明确的故障范围；pstore 未保留 panic
文本，因此不将其表述为已经证明的单一指令。

## 惰性核心修订（本地已完成，尚未刷写）

- `init_sched_ext_class()` 现在只保留 BTF 可见的常量，不分配 DSQ、CPU 掩码、每 CPU
  调度上下文，也不初始化任务列表。
- 只有用户空间注册 `struct_ops` 时，`scx_ops_enable()` 才初始化这些运行时资源，并为
  已存在的任务建立上下文。
- 未注册策略时 `scx_pre_fork()`、`scx_fork()`、`scx_post_fork()` 均直接返回；尤其是
  `dup_task_struct()` 继承 KABI 指针的场景会被显式清空，避免错误继承父任务上下文。
- 完整 Image 已编译成功。与稳定基线相比，配置唯一功能差异仍是
  `CONFIG_SCHED_CLASS_EXT=y`；`task_struct=4800`、`rq=3840`，外置 349 个模块的 CRC
  mismatch 均为 `0`。报告中的 237 个 missing export 是原有 vendor 模块相互供给项，
  与稳定基线相同，不是新增的 CRC/ABI 不兼容。

此版本尚缺 Android 端原生 `libbpf` loader 和一次默认关闭态的 9008 引导验证，故不能
称为可用的风驰调度版本，更不能接入 Scene。

### r3 的明确空指针路径

随后对已编译的 r3 调度路径作了静态回溯，定位到一个可复现的逻辑错误：

1. CPU 从 idle 切出时，`put_prev_task_balance()` 调用导入的
   `for_balance_class_range()`。
2. 该宏在 `prev->sched_class == idle_sched_class` 时即使 `scx_enabled()==false`，仍以
   `ext_sched_class` 为首项。
3. 它因此调用 `balance_scx()`；r3 的惰性设计尚未注册 `struct_ops`，故
   `rq->scx == NULL`，而 `balance_scx()` 的第一处访问就是 `rq->scx->local_dsq`。

这解释了 r3 首屏阶段的挂死。原始上游 core 在启动时预分配 `rq->scx`，所以该宏隐含
该前提；本移植的惰性化必须同时恢复 SCX 关闭态的原厂类遍历。修订后，SCX 关闭时改用
稳定内核原有的 `for_class_range()`，只有策略实际启用才进入 `for_balance_class_range()`。
`kernel/sched/core.o` 已用候选配置编译通过。此修订尚未再次刷写。
